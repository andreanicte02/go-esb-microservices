Qué hubo que cambiar para Kubernetes

En Docker Compose (2021) todo funcionaba porque nada se movía. En Kubernetes los pods se reemplazan en cualquier momento, y eso sacó a la luz estos problemas:

Problema en 2021Qué pasabaSolución
Registro una sola vez al arrancarSi el ESB se reiniciaba, olvidaba todas las rutas y nadie volvía a registrarse.Cada servicio se vuelve a registrar cada 3 s (comun/registro.go); el ESB ignora los repetidos.
Arrancar antes que el ESBresp.Body.Close() sobre una respuesta nil: el servicio se caía y Compose lo reiniciaba.Reintentos con espera creciente; el pod solo se marca listo (/readyz) cuando el ESB ya lo conoce.
Apagado inmediatoAl reemplazar un pod, las peticiones de los últimos segundos recibían connection refused.Graceful shutdown: deja de estar listo, sigue atendiendo 5 s y cierra limpio (comun/servidor.go).
El ESB nuevo no conoce rutasUn pod recién creado responde 503 hasta que llegan los heartbeats.Durante sus primeros 8 s, una petición a una ruta desconocida espera a que se registre.
Rutas recién publicadaskube-proxy tarda un instante en enrutar a un pod nuevo.El ESB reintenta solo si la conexión fue rechazada: la petición nunca llegó, así que es seguro.
El ESB rearmaba los cuerposmarcar_pedido nunca recibía idPedido: siempre marcaba el pedido 0.El ESB reenvía el cuerpo tal cual y devuelve el código real (502/503 en vez de un 200 vacío).
Registro sin candadoPeticiones concurrentes escribían el mismo slice: data race.sync.RWMutex, probado con go test -race.
Imágenes de casi 1 GB, solo amd64golang:latest con el compilador adentro y GOARCH=amd64 fijo.Build en dos etapas: imágenes distroless de 15 MB, sin root, para cualquier arquitectura.

Lo que sigue pendiente, a propósito: el ESB y los pedidos viven en memoria, así que cada uno corre con una sola réplica y el restaurante pierde sus pedidos al reiniciarse (la prueba lo verifica). Escalar a varias réplicas necesitaría guardar ese estado afuera, por ejemplo en Redis.

Correrlo en tu máquina

# con Docker, kind y kubectl instalados
kind create cluster --config k8s/kind.yaml
for s in esb cliente restaurante repartidor; do
  docker build -t esb-microservices/$s:dev -f $( [ $s = esb ] && echo esb || echo servicio-$s )/Dockerfile .
  kind load docker-image esb-microservices/$s:dev --name esb
done
kubectl apply -k k8s
python3 tests/e2e.py          # el mismo reporte que esta página
kind delete cluster --name esb
